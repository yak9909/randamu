## 0. 設計思想（利用者、2026-11-28）

**ノードベースだが、簡単にも操作でき、複雑さを展開してカスタマイズもできる。**

1. **ある形のグラフは平易に見せる。** 一本道（や木の形）のグラフは、フィルタの積み重ね（AE のエフェクトの並び、以前の仕様書の Modifier 01 / 02 …）として見せる。
2. **コードに展開して編集できる。** ノードエディターで算数のノードをちまちまつなぐより、`(a+b)/c+1` と書けた方が楽なことがある。AI にとっても、コードを直接書ける方が楽。
3. **コードとノードは相互に変換できる。** コードを読むことは、結局グラフ（構文木）を作ることだから。数式をノードに展開する方法も、ノードを数式にまとめる方法も用意する。
4. **ノードの接続構造がそのままコードの構造になる**（助言者）。ノード＝関数、線＝引数。Position のような個々のノードについて「コードでどう書くか」を別に考える必要はない。考えるべきは**ノードの種類と意味**（特に Field の評価の文脈とループ）であり、それが決まればコードはそれに従う。
5. **Grid・Circle などの配置は、基本のノードを組んだグループ（Blender のノードグループ、コードでは関数）にする。** 開けば中身が見え、コピーして自分の配置を作れる。

**目標:** プリセットとマクロだけで使える人、積み重ねの表示で足し引きする人、ノードで組む人、コードや AI で書く人が、同じ 1 つのグラフを触る。

**目標にしないこと:** 粒どうしの衝突など前のフレームの状態が要るもの（v4 の 5 節のまま、別のプラグイン）。Web の画面（利用者の決定）。

**失敗とみなすこと（動いても）:**
- コードとノードを往復すると意味が変わる、または中身の見えない箱（ノードにできないコードの塊）が生まれる。
- コードやノードで書き直しただけで、乱数や要素の ID が変わって絵が飛ぶ（11 節）。
- 簡単な使い方（プリセット＋マクロ、積み重ね）に、ノードやコードの知識が要る。

## 2. 全体像

```
            ┌──────────── 1 つのグラフ（保存されるのはこれ。7 節）────────────┐
 見せ方:    │  ノード表示            積み重ね表示              コード表示      │
            │  (自由に組む)          (木の形の部分を平易に)    (文字で書く・AI)│
            └─────────────────────────────────────────────────────────────────┘
                     ↑ どの表示で変えても、同じグラフが変わり、AE の取り消し 1 回分になる
```

- **グラフ**は、ノードと線の集まり。線には 2 種類ある: **ジオメトリ**（要素の並び）と**値**（数・整数・真偽・ベクトル・色）。v4 と P1 は前者だけだった。
- **値の線**は、単一の値（そのノードでどの要素にも同じ）か、**Field**（要素ごとに違う値。5 節）を運ぶ。
- **マクロ**（Effect Controls の Macro 1〜32・Int Macro 1〜32・Color Macro・Point Macro）は、値を出すノードとして扱う（4.4 節）。v4 の「基準 ＋ Σ 深さ × マクロ」は、ただの式 `base + depth * m1` になる。

## 3. 型

| 型 | 中身 | コードの書き方 |
|---|---|---|
| Geometry | 要素の並び（4 節） | 変数 |
| Float | 実数 | `1.5` |
| Int | 整数 | `3` |
| Bool | 真偽 | `true`・`a < b` |
| Vector | 3 次元（x, y, z） | `vec(1, 2, 0)`・`v.x` |
| Color | RGBA（直線の値）。P4 で使う | `rgb(1, 0.5, 0)` |
| Rotation | 回転（3×3 の行列を持つ。度で書く） | `rot(x, y, z)` |

- 値の型には「単一」と「Field」の 2 つの形がある。単一の値はどこにでもつなげる（全要素に同じ値として広がる）。Field は Field を受け付ける入力にだけつなげる。
- **構造の入力**（要素の数や並びを決めるもの: Points の Count、Repeat の回数、選択肢の類）は**単一の値だけ**を受け付ける（v4 の 2 節の「要素ごとの Modulator はつなげない」と同じ）。単一の値は、定数・マクロ・`time`・`seed` と、それらの計算から作れる。エディターとコードの読み取りは、Field を構造の入力につなぐことを拒み、理由（「Count は要素ごとに変えられない」）を出す。
- **割り算:** `/` はいつも Float の割り算（`3 / 2` は 1.5）。切り捨ての整数の割り算は関数 `floordiv(a, b)`、余りは `%`（負の数では床の割り算に合わせる。Python と同じ）。（実装時の判断、11/28: 当初は `//` を床の割り算にしていたが、`//` は注記の始まりでもあり `x = 1 // note` と区別できないため、`//` は注記だけにした。）（レビューの指摘: Int どうしの `/` を切り捨てにすると、Grid の `u = ix / (cx-1)` が 0 か 1 になり、`(cx-1)/2` で格子が半マスずれる。）
- 暗黙の変換: Int → Float、Float → Int（構造の入力では v4 の 8.1 節の丸め。四捨五入・0.5 は 0 から遠い方へ）、Bool → Int / Float（0 / 1）、Float → Vector（3 つとも同じ値）。それ以外の変換は関数（`len(v)` など）で書く。

## 4. 要素と属性

### 4.1 要素が持つ属性

v4 の 2 節の要素を、属性の集まりとして持つ。

| 属性 | 型 | 意味 |
|---|---|---|
| `id` | Int（64 ビットのハッシュ） | 生まれた経路で決まる固定の番号（11 節）。乱数の元 |
| `index` | Int | 並びの中の位置（0 から） |
| `count` | Int（単一） | 並びの数 |
| `position` | Vector | 位置（レイヤーの画素、原点はレイヤーの中央、y 下向き、z 奥向き） |
| `rotation` | Rotation | 向き（v4 の basis） |
| `scale` | Vector | 大きさ（Copy Scale 100% のときの Source に対する倍率） |
| `opacity` | Float | 0〜1 |
| `source` | Int | −1 ＝ 自分のレイヤー、0〜7 ＝ Layer 1〜8 |
| `visible` | Bool | 描くか |
| `weight` | Float | 効き目（v4 の Modify の Weight） |
| `q`・`s` | Float・Int | Order（v4 の 2.4 節の q と段 s）。既定は Index の Order（`q = index / (count − 1)`、`s = index`）。**Set Order**（組み込みのグループ）で v4 の 2.4 節の表の Order（Distance・X / Y / Z・Random・Parent / Child・A / B / C）に付け替える。LFO・Stagger・Cascade の要素ごとのずれは `q`・`s` を読む（v4 の 2.3 節） |
| `color`・`t_i`（開始時刻）など | | P3 以降（v4 の 4・5 節） |

### 4.2 名前付きの属性

- 要素に任意の名前の属性を足せる（Blender の Named Attribute）。`store(g, "ix", 式)` で書き、Field の中では `ix`（名前のまま）で読む。
- 組み込みのグループは、配置ならではの値を名前付きの属性として残す（6.1 節の表）。例: Grid の `ix, iy, iz`（何列目・何行目・何層目）と `u, v, w`（0〜1）、Circle の `angle` と `t`。
- **名前の解き方（筆者の判断。打ち間違いを黙って 0 にしない）:** コードの読み取りは、名前を次の順に探す: ① ブロックの中のローカル、② 文の変数、③ グループの引数、④ 4.1 節の組み込みの属性と 4.4 節の値、⑤ その文脈の並びに**あると分かっている**名前付きの属性（上流の `store` と、組み込みのグループが 6.1 節の表で残すと決めたものを、グラフをさかのぼって調べる）。どれにも当たらなければ「知らない名前」の誤りにして、読み取りを拒む。
- `store` で組み込みの属性と同じ名前は使えない（誤り）。同じ名前の名前付きの属性をもう一度 `store` したら上書き。
- ⑤ で分からないもの（中身の分からない知らない種類のノードを通った並びなど）は、`attr("名前")` と書けば読める（なければ 0 と警告）。
- **ノード表示との関係（2 回目のレビューの指摘への対応）:** ノード表示では、Named Attribute ノードに任意の名前を入れてどの並びにもつなげる（なければ 0 と警告）。書き出すときは、⑤ で並びにあると分かる名前は裸の名前で、分からない名前は `attr("名前")` で書く。こうすれば、書き出したコードを読み取りが拒むことはない。

### 4.3 Instance の親

- Instance（入れ子。格子の各点に円）の後では、子の要素は親の属性を `parent.<名前>` で読める（`parent.index`・`parent.ix`・`parent.position` など）。子の要素を作るとき、親の属性を `parent.` を付けて写しておく。
- 何段も入れ子にしたときは `parent.parent.index` と書く。

### 4.4 値を出すノード（入力のノード）

| ノード | コード | 単一か Field か |
|---|---|---|
| Position・Index・ID・Rotation・Scale・Opacity・名前付きの属性 | `position`・`index`・`id` …・`ix` | Field |
| Count | `count` | 単一（文脈の並びの数） |
| Time | `time` | 単一（秒、レイヤーの時間） |
| Seed | `seed` | 単一（Random Seed） |
| Macro | `m1`〜`m32`（Float）、`i1`〜`i32`（Int）、`cm1`〜`cm8`（Color）、`pm1`〜`pm8`（Point、Vector） | 単一 |
| Random | `random(salt: 0x3fa1)`（0〜1。hash(id, seed, salt)、v4 の 2.4 節） | Field |
| Noise | `noise(position * f, time)` | Field |

- マクロは、Effect Controls で付けた番号のまま書く（v4 の 1.1 節で、名前は付け替えないと決めたため）。エディターとコード表示では、名前の付いたマクロを `m1 /*Spread*/` のように注記で見せる。コードの読み取りは名前でも受け付ける（`macro("Spread")` を `m1` に直す）。
- **使っていないマクロ（利用者の決定、2026-11-28）:** マクロが持つ状態は**使われているか**と**名前**だけ。「解放」の操作は作らない（線を外しても名前・範囲・AE の値とキーはそのまま残る）。
  - 「使われている」は、グラフのどこかがそのマクロを読むこと（Macro ノードからの線、または Expression ノードの式の中の `m1` など）。
  - **エディターの Macros の欄:** 使われているマクロだけを出す。使われていないマクロは隠す。ただし**名前を付けたもの**は、欄の下の「unused」の見出しの中に畳んで出す（開けば名前が見え、値へドラッグしてつなぎ直せる）。名前のない使われていないマクロは出さない。
  - **Effect Controls:** 今のまま（v4 の 1.1・8.1 節）。使われていないマクロの行は隠し、キーかエクスプレッションがあれば出す。
  - **Expose（v4 の 8.1 節）:** 空いているマクロは「使われておらず、名前もない」もの。名前の付いた unused は空きに数えない。空きがなければ Expose は押せず、「空いているマクロがありません（unused のマクロの名前を消すと使えます）」と出す。名前は今のとおりダブルクリックで変えられ、空にもできる。
- Int Macro は Effect Controls の後ろに足す（v4 の 1.3 節で決定）。**Disk ID 69 ＝ グループ「Int Macros」の始まり、70〜101 ＝ Int Macro 1〜32（マッチ名 `DupliX2-0070`〜`DupliX2-0101`）、102 ＝ グループの終わり**（筆者の判断。出した後は変えない）。

## 5. Field の文脈（いちばん大事な決まり）

**Field は、それをつないだ入力のノードが処理している並びの、要素ごとに評価する**（Blender の Geometry Nodes と同じ）。

```
g = grid(10, 10, 50)
g = set_position(g, position + vec(0, sin(index * 0.3) * 20, 0))
```
- `position` と `index` は、`set_position` が処理している `g` の要素の値。
- 1 つの Field を 2 つのノードにつなぐと、それぞれの並びで別々に評価する（同じ式でも、並びが違えば値も違う）。

**ノードごとの文脈:**

| ノードの種類 | Field の入力を評価する並び |
|---|---|
| Set 系・Store（ジオメトリの入力を 1 つ持ち、要素を書き換える） | そのジオメトリの入力 |
| 基本の Generator（Points など、作る数が構造の入力で決まる） | **これから作る要素**（`index` は 0〜Count−1、`count` は Count）。要素を作るときに評価する |
| Instance | 子の要素（`parent.` で親を読む） |
| Morph など入力を 2 つ以上持つもの | そのノードの説明に書く（既定は出力の並び） |

- **Generator の入力にも Field を入れられる**（Blender にない、DupliX の決まり）。例: `circle(count: 36, radius: 100 + index * 5)` は外へ広がる螺旋。構造の入力（Count）は単一の値だけ（3 節）。
- 別の並びの値を読むには、文脈を明示するノードを使う:
  - `at(h, i).position` … 並び `h` の `i` 番目の要素の値（Blender の Sample Index）。`i` は Field でよい（例: `at(g, index - 1).position` で 1 つ前の要素）。範囲の外は端の要素に寄せる（既定。`wrap: true` で回る）。
  - `nearest(h, position).position` … 並び `h` のうち一番近い要素（P7。kd 木）。
- **Accumulate:** `accumulate(値)` は、文脈の並びの `index` の順で、その要素までの和（`exclusive: true` で手前まで）。並列に計算できる（前方の和）。
- Field は**構造を変えない**: 要素の数・順番・ID を変えるのはジオメトリのノード（Points・Merge・Instance・Delete・Sort など）だけ。

### 5.1 コードでの書き分け: 関数（Field）か、写した値か（利用者の決定、2026-11-28）

Field は「要素を 1 つ受け取って値を返す関数」（コールバック）。呼ぶのはつないだ先のノードで、その並びの要素ごとに呼ぶ。コードでは次の 3 つを見た目で書き分ける。

| 書き方 | 意味 | ノード |
|---|---|---|
| ノードの引数にその場で書く式: `set_position(g, position + vec(0, index * 10, 0))` | Field（関数）。`(e) =>` を省いてよい。`position` は「渡された要素の位置」 | 値のノードの木（Position・Index・Expression など） |
| 変数に入れる関数: `p = (e) => e.position + e.index * 10` | Field（関数）。**変数に入れるときは `(e) =>` を必ず書く** | 同上（変数は線に名前を付けるだけ） |
| 写した値: `b = g.position`（`g.<属性>`、`g.(式)` も可） | その文の時点の `g` の各要素の値を写したもの | **Capture**（Blender の Capture Attribute。下） |

- **`p = position` は誤り**にし、「関数として入れるなら `p = (e) => e.position`、今の値を写すなら `p = g.position`」と案内する（値か関数かが見た目で分からないと混乱するため。利用者との話し合いで決定）。
- 変数に入れた関数は、どの並びにも結び付かない（参照ではない）。`g` に使えば `g` の要素で、`c` に使えば `c` の要素で計算する。
- **変数に入れた関数の使い方:** 省いた形の式の中では名前で書く（`set_position(g, p + vec(0, 10, 0))`。関数どうしの足し算は関数）。`(e) =>` の中では `p(e)` と呼ぶ。グループの引数にも渡せる（Field を受け付ける引数）。
- `(e) =>` の中では `e.position`・`e.index`・`e.<名前付きの属性>`・`e.parent.index` と書く。省いた形の名前（`position`）と混ぜない（`(e) =>` の中で裸の `position` は誤り）。名前付きの属性の名前は、書いた時点ではなく**関数を使う所で**、その並びにあるかを確かめる（4.2 節の ⑤）。
- 書き出し（8.2 節）: 使う先が 1 か所の Field は、その引数に省いた形で埋め込む。2 か所以上で使う Field は `name = (e) => …` の文にし、使う所では `name` と書く。

**Capture の作り（2 回目のレビューを受けた筆者の判断。Blender と同じ）:**
- Capture は**ジオメトリのノード**（ジオメトリの入力 1・ジオメトリの出力 1・値の出力 1）。`g` の流れの途中に入る。値は、写し取った要素に**名前のない属性として乗り**、その要素と一緒に下流へ流れる（ID の表で突き合わせるのではない）。
- そのため、下流で要素が並べ替えられても（Sort）、一部が消えても（Delete）、値は同じ要素に付いたまま。Merge では、Capture を通った入力の要素だけが値を持ち、ほかの入力の要素は 0（名前付きの属性と同じ）。Instance の子からは `parent.b` で読める（写した値も `parent.` で読める）。Morph は名前付きの属性と同じ扱い（数・ベクトルは補間、それ以外は進み具合 0.5 で切り替え）。
- コードでは、`b = g.position` の文の**後の `g` は Capture の出力**を指す（流れの途中に入るため）。書き出しは、Capture の入力のノードの出力がほかのどこにも使われていないとき `b = g.position` と書き、使われているとき（Capture の前と後の両方を使う）は明示の形 `g_b, b = capture(g, position)` と書く。どちらの形も読める。
- 8.1 節の「`name = 式` はノードを増やさない」の例外は、この Capture だけ。

## 6. ノードの種類

### 6.1 組み込みのグループ（開いて中身を見られる配置）

基本のノード（6.2 節）を組んだもの。ノード表示では 1 つのノード、積み重ね表示では 1 行、コードでは関数呼び出し。開くと中身が見え、「自分用にコピー」で編集できる（12 節）。

| グループ | 入力（**太字**は構造の入力） | 残す名前付きの属性 |
|---|---|---|
| Grid | **Count X / Y / Z**、Spacing X / Y / Z | `ix, iy, iz`、`u, v, w` |
| Circle | **Count**、Radius、Start Angle、Sweep、Align（Off / Outward） | `angle`、`t`、`normal`（外向きの単位ベクトル） |
| Line | **Count**、Length、Angle | `t`、`normal`（線の左手側） |
| Spiral・Rose・Polar・Sphere・Torus・Fibonacci | 各配置の数と大きさ | `t`・`u, v` など |
| Transform | Position・Rotation・Scale・Pivot（v4 の 8.1 節の定義） | |
| Modify | Position・Rotation・Scale・Opacity（v4 の 8.1 節の掛け方、Weight を掛ける） | |
| Source | First Layer・Layer Count・Assign（v4 の 8.1 節） | |
| LFO・ENV・Stagger・Cascade | v4 の 2.3 節（値を出すグループ。要素ごとのずれは `index`・`id` の Field で書く） | |
| Absorb など v4 のプリセット | v4 の 2.5 節 | |

- 例（Grid の中身）:
```
group grid(cx: int structural = 5, cy: int structural = 5, cz: int structural = 1,
           sx = 100, sy = 100, sz = 100) {
    g  = points(cx * cy * cz)
    g  = store(g, "ix", index % cx)
    g  = store(g, "iy", floordiv(index, cx) % cy)
    g  = store(g, "iz", floordiv(index, cx * cy))
    g  = store(g, "u", ix / max(cx - 1, 1));  …          // `/` は Float の割り算（3 節）
    return set_position(g, vec((ix - (cx - 1) / 2) * sx, (iy - (cy - 1) / 2) * sy, (iz - (cz - 1) / 2) * sz))
}
```

### 6.2 基本のノード（C++ で作る）

| 分類 | ノード |
|---|---|
| ジオメトリを作る | **Points**（数だけ作る。位置は原点）、**Path**（AE のマスクを読む）、**Mask Vertices**、**Layer Alpha**（v4 の 2 節のキャッシュ）、**Polyhedron**（表を引く）、**Scatter**（偏りの少ない乱数の列） |
| 要素を書き換える | **Set Position**・**Set Rotation**・**Set Scale**・**Set Opacity**・**Set Source**・**Set Visible**・**Set Weight**・**Store**（名前付きの属性）。どれも Selection の入力（`where:`）を持つ |
| 並びを変える | **Merge**、**Instance**、**Delete**（`where:` が真の要素を除く）、**Sort / Shuffle**（v4 の 2.2 節）、**Morph**・**Pair**・**Move To Target**（v4 の 2.5 節） |
| 値 | 4.4 節の入力のノード、**Math**（下）、**At**、**Nearest**、**Accumulate**、**Switch**（`cond ? a : b`）、**Capture**（5.1 節） |
| 集計（並び全体から単一の値） | **Bounds**（`bounds(g, position)` → `.min`・`.max`・`.center`）、**Reduce**（`sum`・`min`・`max`・`mean`。`max_of(g, len(position))` など）。Transform の Pivot の Center、Order の Distance・X / Y / Z に使う |
| レイヤーの情報 | **Layer Set**（`layer_set(k)`、Layer k に AE のレイヤーが入っているか。単一の Bool。Source のグループが使う） |
| ゾーン | **Each**（9 節）、**Repeat**（10 節） |
| 出口 | **Output**（Copy Scale・Blend・Canvas。v4 の 2.2 節） |

- **Math** は算数・比較・論理・関数（`+ − * / % ** == != < <= > >= && || !`、`sin cos tan asin acos atan2 sqrt abs floor ceil round min max clamp mix smoothstep len normalize dot cross`）と、**回転の演算**（`rot(x, y, z)`（AE の順 R ＝ Rz・Ry・Rx）、`a * b`（回転の合成）、`r * v`（ベクトルを回す）、`inverse(r)`、`slerp(a, b, t)`、`axis_x(r)` など）。Transform の「配置を回す」と Modify の「コピー自身の軸で回す」（`rotation * rot(…)`）はこれで書く（2 回目のレビューの指摘: これがないと組み込みのグループを基本のノードで書けない）。
- **演算のノードは、演算子を選ぶ形にする（利用者の決定、2026-11-28。Blender と同じ）:** 演算ごとにノードの種類を分けない（追加の一覧が長くなるため）。ノードの種類は **Math**（Float・Int の算数と数の関数）、**Vector Math**（ベクトルの演算）、**Compare**（比較。出力は Bool）、**Boolean Math**（`&& || !`）、**Rotate**（回転の演算）の 5 つで、どれもノードの上の選択欄で演算子を選ぶ。
  - 演算子によって入力の数と出力の型が変わる（`sin` は入力 1 つ、`clamp` は 3 つ、Vector Math の `dot` は Float を出す）。**使わない入力は隠す。隠した入力につながっていた線は外さずに残し、効かなくする**（Blender と同じ）。演算子を戻すと線も効き直す。出力の型が変わって、出力の先の入力と型が合わなくなった線は赤く表示して効かなくする（外さない）。
  - **保存**では、ノードの種類は 5 つの名前（`math`・`vmath`・`compare`・`boolmath`・`rotate`）で、演算子は `op=`（7 節）。**コード**では演算子ごとの名前で呼ぶ（`math_add(a, b)`・`math_sin(x)`・`vmath_dot(a, b)`・`compare_lt(a, b)` など。8.1 節）。演算子の名前の一覧は作る人に任せる（18 節）。
  - **効かない線の書き方（3 回目のレビューの指摘、筆者の判断）:** 隠した入力の線と、型が合わなくて赤くした線は、コードでは `_` を付けた名前の引数で書く（`math_sin(x, _b: y)`）。読み取りは `_` の付いた引数の型を確かめず、効かない線として読む。こうすれば往復で消えない。
  - Expression ノードの式を書き換えて出口が Field になり、それが構造の入力につながっていたときも、その線を赤くして効かなくする（書き換えは拒まない。「Count は要素ごとに変えられない」と出す）。
- 式をまとめて持つ **Expression ノード**は 8.3 節。
- **Delete について（v4 との違い、筆者の判断）:** v4 の Mask は「要素を取り除かない」と決めていた（Mask を動かしたときに番号が飛ばないように）。v5 でも、要素を見えなくするのは Set Visible を勧める（積み重ね表示の Mask はこれ）。ただ、取り除きたい用途もあるので Delete も置く。Delete の後は `index` と `count` が詰まる。ID は変わらない。

## 7. 保存の形

- 保存するのは**グラフ**（v4 の 8.1 節の行の形を版 2 に上げる）。コードは保存せず、表示のたびにグラフから書き出す（8.2 節）。理由: ノードの位置・知らない種類のノードの保持・取り消しの比較を、今の形のまま使えるため。
- 版 2 で足す文:
  - `node <id> <type> <x> <y> key=<key>`（`key` は 11 節の固定の名前）
  - `link <to-node> <input> <from-node> <output>`（値の線。v4 のマクロのつなぎ `param … link m1 depth` は、版 1 を読むときに Math のノードに直す）
  - `const <node> <input> <value>`（線のない入力の値）
  - `group <name> <version>` … `end`（利用者が編集したグループの定義。中は同じ文）
  - `expr <node> "<式>"`（Expression ノードの中身。複数の行は `\n` で 1 行に書く。8.3 節）
  - 演算のノード（6.2 節）は `node <id> math <x> <y> key=<key> op=<演算子>`。P1.5 の実装で保存した `math_add` などの種類のノードは、読むときに `math` と `op=add` に直す（Vector Math などの残りも同じ）
- 版 1（P1 で作ったグラフ、利用者の試用のもの）は読める。マクロのつなぎは、式 `base + depth * m1` を持つ **Expression ノード 1 つ**に直す（演算のノードの木にはしない。読みやすく、積み重ね表示の深さのつまみ（14 節）が見つけられる形にするため。3 回目のレビューの指摘、筆者の判断）。書くときは版 2。
- ユーザーのグループの `group <name> <version>` の版は、いつも 0（版は組み込みのグループのためのもの。12 節）。
- .dx2graph（グラフのファイル）も同じ形。コードの書き出し・読み込み（.dx2 のテキスト）も用意する（AI に渡す・AI から受け取る用）。

## 8. コード

### 8.1 言語（ノードの接続構造をそのまま書いたもの）

```
// 格子の各点に、親の列ごとに向きの違う小さな円
g = grid(cx: i1, cy: i1, sx: m2, sy: m2)          // i1 /*Count*/, m2 /*Spacing*/
c = circle(count: 6, radius: 20)
h = instance(g, c)
h = set_rotation(h, rot(0, 0, parent.ix * 15))
each h {
    if t < 0.5 { scale *= 0.5 }
    position += vec(0, sin(time * 2 + parent.index * 0.4) * 10, 0)
}
output(h, copy_scale: m3)
```

| 書き方 | ノード |
|---|---|
| `name = 式` | 式の結果に名前を付ける（線に名前を付けるだけで、ノードは増えない。例外は `b = g.position` の Capture だけ、5.1 節） |
| `h2 = each h { … }` | Each ゾーン（9 節）。出力に名前を付ける |
| `f(a, b, name: c)` | ノード `f`。位置の引数は入力の順、名前の引数は入力の名前 |
| `a + b * sin(x)` など、演算子を使った式 | **Expression ノード 1 つ**（ひとまとまりの式。値のノードの木のうち、演算子・数の関数・入力の値だけでできた最大の部分。出口は 1 つ） |
| `e = expr(k: 3) { x = k * index; y = sin(time) }` | **Expression ノード 1 つ**（出口が 2 つ以上、または線のない入口を持つもの。8.3 節）。使う所では `e.x` |
| `math_add(a, b)`、`math_sin(x)` など、演算子ごとの名前で呼ぶ形 | 演算のノード（6.2 節。演算子を選ぶ 1 つのノード） |
| `v.x`、`vec(x, y, z)` | Separate / Combine XYZ |
| `c ? a : b` | Switch |
| `each g { … }`（文として書く形） | Each ゾーン。出力は読み取りが `g` に続く名前（`g_2`）を key として付け、次に書き出すときは `g_2 = each g { … }` の形で書く |
| `repeat n (x = 初期値, …) { … }` | Repeat ゾーン（10 節） |
| `group name(引数) { … return … }` | グループの定義（関数。12 節） |
| `// …`、`/* … */` | 注記（グラフには残らない。8.2 節） |

- 一つの文はノードを作るか、線に名前を付けるだけ。**ノードにならない文はない**（制御の文は Each と Repeat だけで、どちらもゾーンのノード）。
- 引数の型が合わないとき、構造の入力に Field を渡したとき、輪になるとき（`a = f(b); b = g(a)`）は、読み取りが行と列を付けて拒む。グラフは変えない。

### 8.2 グラフ → コード（書き出し）

- ジオメトリを出すノードは、**必ず** 1 つの文にし、その `key`（11 節）を変数名にする。書き出したコードでは同じ変数名に 2 回代入しない（`s = f(s)` の形は書かない）。
- Expression ノードは演算子の式として、演算のノードは演算子ごとの名前で呼ぶ形（`math_add(a, b)`）として書く（8.1 節の表）。こうすると、読み直したときに Expression ノードと演算のノードの区別が戻る（レビューの指摘への対応）。式で書きたい人は Expression ノードを使うので、関数の形がコードに出るのは、わざわざ演算のノードを置いたところだけになる（2026-11-28 の見直し）。
  - 演算のノードは、使う先が 1 か所なら式の中に埋め込み、2 か所以上なら名前を付けた文にする。
  - Expression ノードは、**出口が 1 つで、線のない入口がない**なら、式の形で書く。入口は、つないだ先で置き換えて書く: 文の変数（名前で）、マクロ・Position などの入力のノード（`m1`・`position` と書く）、使う先が 1 か所の値のノード（`at(g, index - 1).position` のように、その場に呼び出しを書く）。使う先が 1 か所なら引数に埋め込み、2 か所以上なら `name = (e) => …`（Field のとき。5.1 節）か `name = …`（単一の値のとき）の文にする。
  - それ以外の Expression ノードは `name = expr(入口: 値, …) { 出口 = 式; … }` の形で書く（8.3 節）。`expr(…)` の引数には、線のない入口の値と、つないだ先（上と同じ置き換え）を書く。`name` は Expression ノードの key が識別子ならそれ、そうでなければ `<使う先の key>_<入力の名前>` を書き、その名前を新しい key にする（値のノードの key は ID に効かないので変えてよい。11 節）。
  - **読み取りの側（3 回目のレビューの指摘）:** 式の中に書いた `at(…)`・`accumulate(…)` など、式に書けない値のノードの呼び出しは、別のノードにして Expression ノードの入口につなぐ（入口の名前は読み取りが付ける）。式の中の入力のノードの名前（`m1`・`position`）は、式の中でその場で読む（入口にしない）。
- 文の順は、つながりの順（上流から）。同じ順位のものはノードの位置（左から、上から）。
- **書き出しは決まった形**（同じグラフからは毎回同じ文字）。書き出したコードを読み直すと同じグラフになる（試験で確かめる。13 節）。
- 利用者が書いたコードの書式・注記・変数名（`key` 以外）は、読み込んだ時点でグラフに溶け、次に書き出すときは決まった形に戻る（意味は同じ）。注記を残したいときはノードの Label に書く（Label は書き出し時に `// label` として出る）。

### 8.3 Expression ノード（開ける式）と、数式とノードの相互の展開（2026-11-28 の見直し、利用者の決定）

**パラメータ（ノードの入力欄）には式を持たせない。** 式は必ず Expression ノードに書き、線で入力につなぐ。入力欄に式が隠れると、ノード表示でグラフが読みにくくなるため（利用者）。
- ノード表示の入力欄が受け付けるのは定数と、**定数だけの式**（`360 / 12`。その場で値 30 にする）。名前を含む式（`m1 * 2 + index`）は受け付けず、「式は Expression ノードに書いてつなぎます」と案内する。入力欄の右クリック「Expression をつなぐ」で、空の Expression ノードを作ってその入力につなぐ。
- 積み重ね表示（14 節）は例外の見せ方をする: 入力につながった Expression ノードの出口が 1 つで、その Expression ノードの使う先がその入力だけのときは、欄に式を出し、欄で直すと**その Expression ノードの式が変わる**（グラフの決まりは同じ。欄が Expression ノードの窓になるだけ）。定数やマクロの欄に名前を含む式を打つと、出口 1 つの Expression ノードを作ってつなぐ。積み重ね表示では入口を見せられないので、ここで打つ式は**知らない名前を誤りにする**（上の一覧の名前と `attr("…")` だけ。3 回目のレビューの指摘、筆者の判断）。
- コードの引数に書いた式は、今と同じく Expression ノードになる（8.1 節）。

**Expression ノードの見た目と働き（Math Controller のような箱）:**
- ノードの上の複数行の欄に式を書く。各行は `出口の名前 = 式`。名前を省いた 1 行だけの式は出口 `value` になる。**名前が `_` で始まる行は出口にしない**（式の中だけの途中の値。`_d = a * b`。「Expression にまとめる」で、中で 2 か所以上から使うノードはこの形の行になる。3 回目のレビューの指摘、筆者の判断）。
- **出口のソケット**は、`_` で始まらない行の名前ごとに 1 つ。**入口のソケット**は、式の中の**知らない名前**ごとに 1 つ（書いた順）。
- **式が効くのは確定したとき**（Ctrl+Enter、または欄から外へ出たとき。3 回目のレビューの指摘、筆者の判断）。打っている途中では、ソケットも線も変えない。確定で 1 回分の取り消しになる。誤りのある式は確定せず、欄に誤りの位置を出す。
- 知らない名前に**数えないもの**（その場で読む）は、**決まった一覧**: 4.1 節の組み込みの属性（`position`・`index`・`id`・`rotation`・`scale`・`opacity` など）、`parent.…`、4.4 節の値（`count`・`time`・`seed`・マクロ `m1`・`i1`・`cm1`・`pm1`、`random(…)`・`noise(…)`）、`attr("名前")`、式の中で先に書いた行の名前。これらをソケットにすると、Expression ごとに Position ノードをつなぐことになり、かえって読みにくいため（筆者の判断）。
  - **名前付きの属性（`ix`・`angle` など）は一覧に入れない**（16 節の 4、利用者の決定）。一覧を、つないだ先の並び（4.2 節の ⑤）で変えると、線をつなぎ替えただけでソケットが出たり消えたりするため。名前付きの属性は `attr("ix")` で読む。上流にある名前付きの属性と同じ名前を書いたときは、入口の横に「属性なら attr("ix")」と出す。
  - 4.2 節の「知らない名前は誤り」との関係（3 回目のレビューの指摘）: ノード表示の Expression ノードでは、知らない名前は誤りではなく入口になる（利用者の決定）。打ち間違いは、ソケットが増えることで目に見える。コードの `expr { }` の中と式の形では、4.2 節のまま（下）。
- 入口のソケットは Any の型で、つないだ線の型になる。線のない入口は値の欄を持ち（既定 0）、そこに定数を入れられる。
- 式を確定して**なくなったソケットの線は外す**（同じ取り消し 1 回分に含まれる。筆者の判断）。名前が残ったソケットの線は保つ。
- **式の中の `random()`:** 確定したとき、塩（salt）のない `random()` に乱数で塩を付け、式の文字に書き戻す（`random(salt: 0x3fa1)`）。式を書き直しても塩は文字に残るので、乱数は変わらない（11 節。3 回目のレビューの指摘、筆者の判断）。コードの読み取りでも同じ（塩のない `random()` は、key と式の中の何番目の `random` かから作り、書き出しで文字にする）。
- 入口の名前と一覧の名前がぶつかるとき（コードで `expr(t: 3)` と書いたとき）は、入口が勝つ（4.2 節の名前の解き方で、引数が組み込みの属性より先なのと同じ）。
- 出口は、式が要素ごとの名前を読むか、Field の線がつながった入口を読むときは Field、そうでなければ単一の値。
- 式に書けるのは値の部分だけ（演算子・数の関数・Switch の `?:`・`vec`・`rot`・`.x`・上の「その場で読む」名前）。ジオメトリを受け取るもの（`at`・`nearest`・`bounds` など）は式の中に書けない（ジオメトリの入口を持たせないため。これらはノードとして外に置き、その出口を入口につなぐ）。

**グループのように開ける:**
- Tab（または右上の ▸）で開くと、中は**演算のノード（6.2 節）と値の入力のノード（4.4 節）を組んだもの**で、左右にグループと同じ入口・出口の枠がある。中で演算のノードを直すと式が書き直り（決まった形。注記は消える）、式を直すと中が作り直される。式と中のノードは同じものの別の見え方で、保存するのは式だけ。中のノードの位置は保存せず、開くたびに自動で並べる。
- **中に置けるのは式で書けるノードだけ**（利用者の確認、2026-11-28）。ジオメトリのノードやグループは中に置けない（追加のメニューに出さない。外から貼り付けたものは拒む）。これで式と中のノードがいつも 1 対 1 で行き来できる。
- 右クリック「ノードに展開」（Blender の Ungroup）で、中のノードを外に出して Expression ノードを消す（今の `ExpandExpression`）。逆に、演算のノードを選んで「Expression にまとめる」（Ctrl+G と同じ考え）で 1 つの Expression ノードにする。選んだ部分の外への出口が複数あれば、出口も複数になる。
- **グループとの違い（筆者の判断。利用者の「グループの定義が分からなくなるか」への答え）:** グループは**名前の付いた、使い回す定義**で、中を直すと同じグループを使う所がすべて変わる。Expression ノードは**そのノードだけの中身**で、使い回さない。中身の正体は式の文字で、開いた中は式の見え方。だから「グループの一種」にはせず、開ける点だけを同じ操作にする。使い回したくなったら、Expression ノードを右クリック「グループにする」で、1 つの値のグループ（12 節）に写す。

**コードでの書き方:**
```
// 出口が 1 つ・線のない入口がない: 今と同じく式の形
g2 = set_position(g, position + vec(0, sin(index * 0.3) * m1, 0))
// 出口が 2 つ、線のない入口 k
w = expr(k: 3) { x = k * index; y = sin(time * k) }
g3 = set_position(g2, vec(w.x, w.y, 0))
```
- `expr(…)` の引数は入口の名前と、その値（定数）または線の元（変数名・マクロ・式）。`{ }` の中は Expression ノードの式そのもので、Field の名前は省いた形で書く（Expression ノードは見た目で式の箱と分かるので、5.1 節の `(e) =>` は要らない）。
- コードの `{ }` の中の名前は、引数・上の一覧・先に書いた行で解き、それ以外は 4.2 節の順（文の変数は暗黙の入口としてその変数につなぐ。その文脈の並びに分かっている名前付きの属性は `attr("…")` として読む）。どれにも当たらなければ誤り（コードでは打ち間違いを黙って入口にしない）。
- 出口の名前が `value` だけのときは、使う所で `w` と書いてもよい（書き出しは `w`）。

### 8.4 コード表示（エディターの中）

- エディターの表示の切り替え（ノード / 積み重ね / コード）。コード表示は文字の編集欄で、Ctrl+Enter（または「適用」）で読み取り、通ればグラフを置き換えて AE に書く（取り消し 1 回分）。通らなければ誤りの行を示し、グラフは変えない。
- 読み込んだグラフのノードの位置: `key` が同じノードは前の位置を保つ。新しいノードは、つながる先のノードの左に自動で並べる（Blender の Node Arrange のような簡単な規則）。

## 9. Each ゾーン（要素ごとのブロック）

```
each g {
    if angle < 180 { scale *= 2 }
    position += normal * sin(time + t * 6.28) * 20
}
```
- **ループではない。** 中身は Set 系のノードに Field をつないだもの。上の例の中身は次と同じ計算:
  `g = set_scale(g, scale * 2, where: angle < 180)`、`g = set_position(g, position + normal * sin(…) * 20)`。
- **Each はグラフの中の本物のゾーン**（枠のノード。中に Set 系が並ぶ）として保存する（筆者の判断。レビューの指摘: 書き方の上だけのものにすると、往復で枠が出たり消えたりする）。コードの `each` は必ず Each ゾーンになり、Each ゾーンは必ず `each` として書き出す。枠の外に並んだ Set 系は、何個続いても別々の文として書き出す（自動でまとめない）。ノード表示で Set 系を選んで「Each にまとめる」、Each を右クリックで「ほどく」。
- 中で読める名前: 4 節の属性と名前付きの属性、`parent.…`、単一の値。代入できるのは属性（組み込みと名前付き。新しい名前に代入すると Store になる）と、ブロックの中だけのローカル。
- **ブロックの中は上から順に読む**（普通のプログラムと同じ）。ブロックの中の文は上から順に効く（2 つめの文は 1 つめの結果を読む）。
- **ローカル**（`old = position`）は**その文の時点の値**を持つ。グラフでは、ローカルは**いつも Capture**（5.1 節）になる。ブロックの中でも `name = (e) => …` で関数を入れられ、こちらは使う所の値で計算する（5.1 節と同じ）。
  - 書き出し: ゾーンの中の Capture はローカル（`old = position`）、2 か所以上で使う Field は `name = (e) => …` として書く。ノード表示で 1 つの Field を、位置を書き換える前と後の 2 つの Set につないだものは関数として書き出す（値の写しにしない）ので、読み直しても意味は変わらない（2 回目のレビューの指摘への対応）。
- **`if` の条件は、`if` の文の時点で 1 回だけ評価する**（2 回目のレビューの指摘: 文ごとに条件を評価し直すと、`if scale.x < 1 { scale *= 2; position += v }` で 1 つめの文が scale を変え、2 つめが効かなくなる）。グラフでは、条件を名前のない Capture で写し、中の Set 系の Selection にはその値をつなぐ。`else` の枝は否定をつなぐ。
- **key:** Each ゾーンの key は出力の変数名（`g_2 = each g { … }` の `g_2`）。中の Set 系・Capture の key は `<ゾーンの key>.<中の文の番号>`（`g_2.1`）で、コードには出さない（中のノードは ID に効かないため、識別子である必要はない）。
- 文として書く形 `each g { … }` は、後の `g` がゾーンの出力を指す（5.1 節の Capture と同じ規則）。書き出しはいつも `g_2 = each g { … }` の形。
- ブロックの中で、ほかの要素の値（`at`）や Accumulate も使える（文脈はブロックの並び）。
- ノード表示では、囲みの枠（Blender の Zone）の中に Set 系のノードが並ぶ。

## 10. Repeat ゾーン（状態を持ち越すループ）

```
// 1 つ前の結果から次を作る（単純な L-system 風の枝分かれ）
g = points(1)
r = repeat 4 (geo = g, len = 100.0) {
    child = set_position(points(2), vec((index - 0.5) * len, -len, 0))
    geo = instance(geo, child)
    len = len * 0.6
}
output(r.geo)
```
- 入口と出口の 2 つのノードで囲む枠（Blender の Repeat Zone）。持ち越す値（ジオメトリでも値でもよい）を入口から出口へ線でつなぐ。**回数は構造の入力**（単一の値）。
- 回ごとに**順番に**計算する（並列にしない）。ただし 1 フレームの中だけで完結し、毎フレーム最初から計算する（前のフレームは使わない）。
- 中で読める `iteration`（0 から）。
- **持ち越す名前への代入は、ブロックの中だけ同じ名前に何度でも代入してよい**（`geo = instance(geo, child)`。8.2 節の「同じ名前に 2 回代入しない」の例外）。最後に代入した値が、次の回のその名前になる。
- **key:** Repeat ゾーンの key は出力の変数名（`r`）。中のジオメトリのノードの key は `<ゾーンの key>.<代入先の名前>`（`r.geo`。同じ名前に 2 回代入したら `r.geo.2`）、名前を付けずに式の中で作ったものは `<ゾーンの key>.<使う先の名前>.<入力の名前>`（`r.child.0`）。中のノードは書き出しでもブロックの中の文として書き、key は識別子でなくてよい（書き出しは中の文を書いた順に並べ、読み直すと同じ key になる）。
- ID: 回の中で作った要素の ID は hash(中のノードの key, 回の番号, 番号) から作る（11 節）。持ち越す並びを Merge の 1 つめの入力に入れる限り、前の回の要素の ID は変わらない（11 節の Merge）。
- 重さの上限: 回数 × 中の要素の数が上限（v4 の 10 万）を超えたら打ち切り、警告を出す。

## 11. key と ID（書き直しても乱数が変わらないように）

- 各ノードは **key**（文字列、グラフの中で一意）を持ち、**一度付いた key はノードが生きている間変わらない**（保存される）。
  - ノード表示で作ったとき: 種類の名前と番号（`grid1`、`circle2`）。
  - コードで新しく作ったとき: 変数名（`g = grid(...)` なら `g`）。利用者が `s = f(s)` のように同じ名前に何度も代入したときは、読み取りが 2 つめ以降に `s_2`、`s_3` と付け、**次に書き出すときはその名前で書く**（書き出したコードは同じ名前に 2 回代入しない。8.2 節）。
  - 式の中に入れたジオメトリのノード（`instance(geo, points(2))` の `points(2)`）は、`<使う先の key>_<入力の名前>`（`geo_2_child`。識別子になる形）。書き出すときは独立の文 `geo_2_child = points(2)` にする（ゾーンの外のジオメトリのノードは、書き出しではいつも独立の文。8.2 節）。利用者がそれを式の中に戻しても、使う先と入力が同じなら同じ key になる。
  - 式の中に埋め込んだ値のノード（Expression・Math）は `<使う先の key>.<入力の名前>`。コードに名前として出ないので識別子でなくてよい。値のノードの key は ID に効かない（Random の salt は別に保存する。下）。そのため**値のノードの key だけは、書き出しが付け直してよい**（`expr(…)` の形で書くときに識別子の名前を付ける。8.2 節。「一度付いた key は変わらない」の例外）。
  - ゾーン（Each・Repeat）の中のノードの key は 9・10 節。
- **版 1（P1）のグラフから来たノード（筆者の判断）:** 版 1 の要素の ID は（ノードの番号, 要素の番号）だった。版 1 を読むと、各ノードに key `<種類><番号>`（`grid3`）と「古い ID の作り方」の印を付け、そのノードの要素の ID は P1 と同じ hash(ノードの番号, 要素の番号) で作る。利用者の試用の絵（Source の Random など）が変わらないようにするため。印はそのノードが生きている間残る。
- **コードを読み直したときのノードの対応:** 変数名が前の key と同じノードは同じノードとみなす（位置・salt・key を引き継ぐ）。対応しないノードは新しいノード。
- **注意（レビューの指摘、残る性質）:** 利用者が `s = …; s = …; s = …` と書いたコードで途中の行を消すと、後ろの `s_3` が `s_2` に変わり、その要素の ID が変わる。書き出したコードは同じ名前に 2 回代入しないので、一度適用した後は起きない。読み取りは、`s_2` のような付け直しが起きたときに「次から名前を分けて書くと乱数が保たれます」と知らせる。
- **要素の ID は key から作る**: 基本の Generator は hash(key, 番号)、グループの中のノードは hash(グループを呼んだノードの key, 中のノードの key, 番号)、Instance は hash(親の ID, 子の ID)、Morph は v4 の 2.5 節（ノードの番号の代わりに key）。
- **Merge の ID（v4 の 2.4 節を変える、筆者の判断）:** 1 つめの入力の要素は**元の ID のまま**通す。2 つめ以降は hash(入力の番号, 元の ID)。（レビューの指摘: Repeat の中で持ち越す並びを毎回 Merge で包み直すと、回数を 4 から 5 に変えただけで、前の回の要素の ID まですべて変わる。1 つめを素通しにすれば、持ち越す並びを 1 つめにつなぐ限り ID は保たれる。）
- そのため、コードで書き直しても、key（変数名）が同じなら乱数と ID は変わらない。変数名を変えると変わる（エディターで key を変えるときは「乱数が変わります」と出す）。
- Random の `salt` は、ノードを作るときに乱数で決めて保存し、コードにも書き出す（`random(salt: 0x3fa1)`）。書き忘れたときは key から作る。
- **組み込みのグループを C++ の実装に差し替えても、同じ ID を出す**（12 節の試験）。

## 12. グループの扱い

- **組み込みのグループ**は名前と版で参照する（`grid@1`）。DupliX の新しい版がグループの中身を直すときは版を上げ、古いグラフは古い版を使い続ける（古い版の定義も DupliX に残す）。見た目が変わらないようにするため。
- **利用者が中身を編集**するときは「自分用にコピー」で、そのグラフの中に定義（7 節の `group`）を写す（Blender が他のファイルのノードグループを取り込むのと同じ）。
- **構造の入力の判定:** グループの入力が、中で構造の入力（Points の Count など）につながっていれば、そのグループの入力も構造の入力（自動）。
- **速さ:** 手を加えていない組み込みのグループ（Grid・Circle・Line・Transform・Modify・Source など）は、同じ結果を出す C++ の実装に差し替えて計算する（P1 の `src/graph/eval.cpp` の実装がそれに当たる）。グループの定義が正解で、差し替えた実装は「要素の値と ID が定義と一致する」ことを試験で確かめる（13 節）。
- 利用者が書いたグループと、差し替えのない組み込みは、Field を配列ごとに計算する評価（13 節）で動く。

### 12.1 コードでのグループ（関数の定義。利用者の決定、2026-11-28）

グループはコードでは**関数の定義**、グループのノードは**関数の呼び出し**にする。
```
group ring(geometry: geometry, count: int = 6, radius = 20) {
    c = circle(count: count, radius: radius)
    h = instance(geometry, c)
    return (geometry: h, center: bounds(h, position).center)
}
r = ring(g, count: i1)
output(r.geometry)
```
- **出口が 1 つ**なら `return h` と書き、使う所では呼び出しの結果をそのまま使う（`h = ring(g)`）。**出口が 2 つ以上**なら `return (名前: 値, …)` と名前を付けて返し、使う所では `r = ring(…)` のあと `r.geometry`・`r.center` と書く（Blender のグループの出口が複数あるのと同じ）。
- **中から読めるもの:** 引数、グループの中の文の変数、4.1・4.2 節の属性、4.4 節の値（`time`・`seed`・`count`・マクロ）。**外の変数（呼ぶ側の文の変数）は読めない**。外を読めると、ノード表示で「線がないのに値が入る」ことになり、開いても中だけで意味が分からないため（筆者の判断）。
- **組み込みのグループの中ではマクロを使わない**（プリセットやマクロの番号の付け替えで意味が変わらないように）。利用者のグループはマクロを読んでよい。
- **引数の名前が組み込みの属性と同じとき**（Circle の `count`、Transform の `position`）は、中では引数が勝つ（4.2 節の名前の解き方の ③ が ④ より先）。
- **`structural` の印は書いても書かなくてもよい**（12 節のとおり、中で構造の入力につながれば自動で構造の入力になる）。書き出しは、自動で決まった結果をいつも書く（読む人に分かるように）。印を書いた引数は、中で構造の入力につながっていなくても単一の値だけを受け付ける。
- **グループの名前は、組み込みのグループや基本のノードと同じ名前にできない**（誤り）。「自分用にコピー」は `grid_copy`、`grid_copy_2` … の名前を付ける。
- **再帰は誤り**（グループが自分を、または回り回って自分を呼ぶ）。ノードで表せないため。繰り返しは Repeat ゾーン（10 節）で書く。
- **グループの定義の置き場所:** 組み込みのグループはコードに定義を書かない（呼ぶだけ）。「自分用にコピー」したグループと利用者が作ったグループは、書き出しでコードの先頭に定義を並べる（つながりの順、同じ順位は名前の順）。コードで書いた `group` の定義はそのグラフのグループになる（7 節の `group … end` で保存）。
- **ノード表示:** Ctrl+G で選んだノードをグループにし、Tab で開く・閉じる（15 節）。開いた中は左右に入口・出口の枠（Blender の Group Input / Output）。グループのノードの右クリック「自分用にコピー」、組み込みのグループを開いた中は読むだけ（直そうとすると「自分用にコピーしてください」）。
- **今の実装の状態（2026-11-28）:** 組み込みのグループ（Grid・Circle・Line・Transform・Modify・Source）は核ではすでにグループ（`src/dxg5/dx5_groups.cpp` に定義のコード、C++ の差し替え、一致の試験）。開く・自分用にコピー・Ctrl+G・コードでの `group` の定義（今は読み取りが拒む）・`group … end` の保存は、まだない（P1.5c の残り）。

## 13. 評価と速さ

- 評価は v4 の 2 節のまま PreRender で行う（結果は要素ごとの属性の配列）。
- **ジオメトリのノード**は、並び全体を受け取って並び全体を返す。**Field** は、つないだ先のノードが、自分の並びに対して配列ごとに評価する（式を小さな命令の列に直し、要素の配列に対して 1 命令ずつ回す。スレッドに分けて並列に）。
- 速さの目安: 要素 1 万・ノード 20 で 1 フレーム 10 ms 以内（v4 の P0 の代わりの計算では C++ 直書きで 5 ms）。要検証。
- Repeat の中は回ごとに順番に計算する（中の Field は並列でよい）。
- **別の時刻での評価（Motion、v4 の 5 節。筆者の判断、詳細は P5）:** `time` は 1 回の評価の中ではいつも単一の値のまま。Motion は基本のノードで、自分の入力（発生源の並び）より上流の部分グラフを、各要素の開始時刻 t_i で**評価し直し**、ID が同じ要素の位置などを「出た位置」として使う。評価し直すときは、`time` もマクロ（`ctx.macro(k, t)` は今もある）もその時刻の値になる。t_i はフレームの刻みに丸め、同じ時刻の評価は 1 回の評価の中で使い回す。Motion 自身の入力（初速・重力など）も t_i で評価する（v4 の 5 節）。**t_i そのものは今の時刻の評価で決まった値を使い**、t_i の時刻で評価し直した結果からは位置・向きなど「出た姿」だけを取る（t_i を読み直さない。t_i が上流の Stagger で決まるときの循環を避けるため）。**重さ:** 生きている要素の t_i の種類（毎秒 30 個・Life 2 秒なら約 60）だけ上流を評価し直すので、上流が重いと何十倍になる。P5 で測り、重ければ上流の評価を時刻ごとにキャッシュする（時刻だけの関数なので、どのフレームから描いても同じ結果になり、原則に反しない）。**評価器は P1.5a から「部分グラフをある時刻で評価する」関数を持つ**（Motion を後から足せるように）。t_i の時刻にその ID の要素がなければ、その要素は描かない。
- **画素を読む Field（Map・Layer Alpha の明るさなど、v4 の 2 節。筆者の判断、詳細は P3）:** 画素は SmartRender でしか読めない。Map を含むグラフは、**グラフ全体の評価を SmartRender で行う**（PreRender では評価しない）。そのとき PreRender は描く範囲を正確に出せないので、Output の Canvas は Auto にできず、手動の範囲（v3 の 7.2 節）を使う（エディターがそう知らせる）。Map を含まないグラフは今までどおり PreRender で評価する。Layer Alpha（点の並びを作る）は v4 の 2 節のとおり Sample Time とキャッシュ。
- 試験:
  - コード → グラフ → コードで同じ文字になる（決まった形のコードについて）。グラフ → コード → グラフで同じグラフになる。「同じ」とは、ノードの種類と key、Expression ノードの式（字句を整えたもの）、線、線のない入力の値、ゾーン（Each・Repeat）の中身がすべて一致すること。ノードの位置は比べない（key のないノードはない。11 節）。
  - **ただし、Expression ノードの分け方は比べない**（筆者の判断）: 使う先が 1 か所の Expression ノードを別の Expression ノードにつないだものは、書き出すと 1 つの式になり、読み直すと 1 つの Expression ノードになる。意味（評価した値）は同じで、ノード表示での分け方だけが変わる。比べる前に、どちらのグラフも「つながった Expression ノードを 1 つにまとめる」正規化をする。同じ理由で、式の形で書いた Expression ノード（8.2 節）の入口の名前は比べない（読み直すと入口の名前がつないだ先の名前になる）。
  - **値のノード（Expression・演算のノード・入力のノード）の key は比べない**（3 回目のレビューの指摘、筆者の判断。ID に効かず、書き出しが付け直すことがあるため。11 節・8.2 節）。比べる前の正規化に、**Expression ノードの入口につながった入力のノード（Position・Macro など）を式の中の名前に畳む**ことも入れる（8.2 節の書き出しは `m1` と書き、読み直すと式の中で読む形になるため）。Random の塩は比べる（乱数が変わらないこと）。
  - 演算のノードは、ノードの種類と演算子（`op`）を比べる。隠した入力（6.2 節）の線と値も比べる（往復で消えないこと）。コードでは、隠した入力の線は `math_sin(x, _b: y)` のように `_` を付けた名前の引数で書く（筆者の判断）。
  - 組み込みのグループの定義（グループのまま評価）と C++ の差し替えが、要素の値と ID で一致する。
  - 版 1 のグラフを読むと、P1 と同じ要素になる（`tests/graph` の既存の試験）。

## 14. 積み重ね表示（平易な見せ方）

以前の仕様書の Modifier 01 / 02 …（15.1 節）と System Designer（15.2 節）の見た目を、グラフの見せ方の 1 つとして作る。

```
┌──────────────────────────────────────────────────────────┐
│ ▾ Instance                                               │
│     ├ Grid               Count X [ i1 Count ▾ ] …        │
│     └ Circle             Count [ 6 ]  Radius [ 20 ]      │
│ ▸ Set Rotation           Z [ parent.ix * 15         ]    │
│ ▸ Each                   position += vec(0, sin(…) …   ✎ │
│ [＋ 追加]                                                 │
└ Output ───────────────── Copy Scale [ m3 Copy Scale ▾ ] ─┘
```
（上が上流＝最初に効くもの、下へ行くほど後に効く。AE の Effect Controls と同じ向き。16 節の 1 で仮に決めた）

- **見せられる形:** Output から、ジオメトリの入力をさかのぼった**木**。ジオメトリの入力が 1 つのノードは 1 行、2 つ以上（Instance・Merge・Morph）は行の下に入力ごとの枝を字下げで出す。
- **値の入力の見せ方:**
  - 定数はスライダー、マクロはチップ（`i1 Count`）。
  - **値のグループ**（LFO・ENV・Stagger・Random・Noise などの組み込み、利用者のグループ）が入力につながっているときは、チップ（`LFO`）にし、▸ で開くとそのグループの入力が字下げの行として出る（シンセのモジュレーションのスロットと同じ見た目）。チップの入力にも同じ規則が効く（定数・マクロ・グループ・式）。グループの出力に「＋ 定数」「× 定数」が付いているだけのとき（`base + depth * lfo(...)`）は、チップに深さのつまみを付けて見せる。プリセットとマクロだけで使う人がコードの文字を読まずに済むようにする（レビューの指摘への対応）。
  - それ以外（自由な式・値のノードの木）は**その部分を書き出したコードの文字**を入力欄に出す。つながっているのが出口 1 つの Expression ノードで、その使う先がこの入力だけのときは、欄で式を書き換えられ、その Expression ノードの式が変わる（8.3 節）。それ以外（演算のノードの木、出口が複数の Expression ノード、ほかでも使う Expression ノード）は文字を読むだけで、クリックでノード表示のその場所を開く。プリセットは、この形にならないように作る（プリセットの値の入力は、定数・マクロ・値のグループ・深さだけにする）。
- **見せられない部分:** 1 つのノードの出力を 2 か所以上で使う（木でなくなる）ところ、Repeat ゾーン。その部分は「（ノードで組まれた部分）」の 1 行にまとめ、クリックでノード表示のその場所を開く。Each ゾーンは 1 行で、中身はコードの文字（✎ でコード表示）。
- **操作:** 行の追加（「＋ 追加」、行と行の間）・削除・並べ替え（ジオメトリの入力が 1 つのノードどうし）・行を開いて入力を見る。マクロのチップをドラッグで入力欄へ（v4 の 1.3 節の要望）。
- **プリセット**（v4 の 1.2 節）は、積み重ね表示でそのまま見える形にする（初めての人が最初に見るのはここ）。
